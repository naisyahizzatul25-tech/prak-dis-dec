Langkah Kerja:Membuat berkas program Vector Clock sesuai struktur class dan logika pada modul.   Menjalankan simulasi program untuk mengamati perubahan nilai vektor pada beberapa proses.   Pembahasan & Penjelasan Berdasarkan Keluaran Terminal:Inisialisasi awal sistem dengan 3 proses ($P_0, P_1, P_2$) menghasilkan nilai vektor [0, 0, 0] untuk masing-masing proses. Pengujian kausalitas menunjukkan hasil bahwa vc0 happens before vc1 bernilai True, sedangkan hubungan konkurensi (vc0 is concurrent with vc2) dievaluasi bernilai False karena memiliki hubungan kausal langsung. Pola pikir sekuensial tidak dapat diterapkan pada model asinkron atau multithreaded karena penyelesaian task bersifat tidak bisa diprediksi (non-deterministik).   Langkah Kerja Program Multithreaded:Menjalankan program contoh multithread yang melibatkan beberapa thread tugas (t1 sampai t5) dengan operasi penundaan waktu (delay).   Mengamati keluaran terminal hingga mendapati variasi urutan penyelesaian task.   Pembahasan & Penjelasan Gambar:Hasil terminal menunjukkan urutan starting serentak, namun urutan selesainya dapat bervariasi bergantung pada penjadwalan CPU (thread scheduler) sistem operasi.   [Lampirkan Screenshot Multithreaded Example di sini]   3.3.1 Data Race / Race ConditionsLangkah Kerja:Menjalankan program simulasi penarikan saldo bersamaan tanpa pengamanan (race-conditions-01.py).   Mengamati hasil keluaran saldo akhir yang menjadi negatif.   Menerapkan solusi pengamanan menggunakan threading.Lock (race-conditions-02.py).   Pembahasan & Penjelasan Berdasarkan Visualisasi dan Terminal:Tanpa lock, dua thread membaca variabel global saldo secara bersamaan sebelum diperbarui, sehingga kedua thread menganggap saldo mencukupi dan melakukan pengurangan ganda yang berakibat saldo bernilai negatif (-60).   Visualisasi alur menunjukkan terjadinya overlapping pembacaan data sebelum penyimpanan nilai baru.   Dengan menambahkan objek pengunci (Lock), blok kode transaksi diatur secara eksklusif (mutual exclusion), memaksa thread kedua menunggu thread pertama selesai sehingga transaksi kedua ditolak karena saldo sudah tidak mencukupi.   [Lampirkan Screenshot Kode dan Output Data Race serta Solusi Lock di sini]   3.3.2 DeadlockLangkah Kerja:Menjalankan program kondisi deadlock (deadlock-01.py) yang melibatkan dua kunci (lock_a dan lock_b).   Mengamati berhentinya program akibat kondisi saling tunggu (hang).   Menjalankan program pencegahan deadlock menggunakan timeout (deadlock-02.py).   Pembahasan & Penjelasan Berdasarkan Visualisasi dan Terminal:Kondisi deadlock terjadi karena adanya circular wait (tunggu melingkar): Thread 1 memegang Lock A dan menunggu Lock B, sedangkan Thread 2 memegang Lock B dan menunggu Lock A.   Pencegahan dilakukan dengan memberikan parameter batas waktu (timeout) pada fungsi penguncian. Jika dalam batas waktu tertentu kunci tidak didapat, thread akan membatalkan proses dan melepaskan kunci yang dipegangnya melalui blok pembersihan (finally), sehingga program terhindar dari kemacetan total.   [Lampirkan Screenshot Kondisi Deadlock dan Solusi Timeout di sini]   3.4 Algoritma RaftPengantar Konsensus:Algoritma Raft digunakan dalam sistem terdistribusi untuk mencapai konsensus, seperti pemilihan koordinator (leader election).   Langkah Kerja:Menjalankan program simulasi konsensus Raft berbasis Python (raft.py).   Mengamati perubahan status node dari setiap langkah (step).   Pembahasan & Penjelasan Berdasarkan Terminal:Pada tahap awal, seluruh node berstatus sebagai pengikut (follower).   Jika waktu tunggu pemilihan (election timeout) terlampaui tanpa adanya sinyal heartbeat dari pemimpin, node akan mengubah status menjadi kandidat (candidate), menaikkan nomor term, dan meminta dukungan suara.   Ketika memperoleh suara mayoritas, node tersebut resmi terpilih menjadi pemimpin (leader) dan mulai mengirimkan sinyal heartbeat serta mengelola penambahan log (append entries).   [Lampirkan Screenshot Output Simulasi Raft dari Step awal hingga akhir di sini]   Kesimpulan   Sinkronisasi waktu fisik menggunakan NTP (Chrony) memastikan keselarasan waktu antar-sistem dengan tingkat presisi yang tinggi.   Penggunaan Vector Clock memungkinkan pelacakan hubungan kausalitas dan urutan kejadian logis dalam lingkungan terdistribusi secara akurat.   Ketiadaan sinkronisasi dan manajemen konkurensi dapat menimbulkan masalah fatal seperti Data Race dan Deadlock, yang dapat diatasi secara efektif menggunakan mekanisme Locking (Mutual Exclusion) dan Timeout.   Algoritma Raft menyediakan pendekatan konsensus yang terstruktur dan handal untuk mengelola pemilihan pemimpin (leader) serta replikasi log pada sistem terdistribusi.
